## Finding: constructor-name collision on the pin (`ctor_collision/`)

`session.ail` failed to check with: `match arm constructor 'ToolFailed' belongs to ADT
'ObservedToolOutcome', not 'ToolOutcome'`. The core's `ports.ToolOutcome` has had `ToolFailed` since
D3 of 013; ABI 8.0's `ObservedToolOutcome` (031 D3) declares another. The probe (`run.sh`, six
two-line consumers) measures v0.33.0's rule:

| consumer | imports | result |
|---|---|---|
| `no_abi` | ports only | clean |
| `ports_first` | ports, then the ABI (unrelated name) | clean |
| `abi_first` | the ABI (unrelated name), then ports | **fails** — the ABI's `ToolFailed` wins |
| `abi_first_named` | as above, `ToolFailed` imported BY NAME from ports | clean |
| `both`, `both_named` | one module using both constructors | **fails** either way |

So: an imported module's constructors enter the importer's table even under a selective import list;
the EARLIEST import wins; a named import binds. `tool_phase.ail` was already clean only because it
imports `ToolFailed` by name. The fix applied here is the same: `session.ail` names `ToolFailed` in its
`ports` import (line-neutral). **What this leaves for the orchestrator:** a module that must build
`ObservedToolOutcome` values FROM `ports.ToolOutcome` values — the P1.4x evidence construction, line X —
cannot name both on this pin (`both_named`). That is Amendment 1's class of defect across modules,
and an ABI rename (`ObservedToolOutcome`'s `ToolFailed`; the sweep found `ToolPending` and `Disabled`
also declared in core, `phase_vocab.ail:1293` and `context_limit.ail:44`, both imported by name where
used) would be a numbered amendment, not this part's. Nothing in R needs it.
