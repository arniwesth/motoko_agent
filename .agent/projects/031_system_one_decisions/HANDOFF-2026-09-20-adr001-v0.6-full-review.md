## Questions to answer explicitly

**Q-1. The configuration channel (N41).** Is host-stamped `ext_config: Json` the right ABI shape, and does it
close the capture class? Check every one of the 30 capturing bindings: can each captured value be expressed as
`Json` — and which capture a *function* value today (handler tables, dispatchers) and must become a `match`? Is
"the host hashes exactly what a callback can read" true — is there any other route by which a named callback can
read registration-time state (module-level `let`, imports, `ext_artifacts`, the transcript)? Does stamping a
possibly large value (cached prompts, tool schemas) on every view have a cost the ADR should state? Is the
per-epoch config digest with append-and-continue consistent with `ext_set_digest` staying kind-only, with
ADR-003 D5, and with the `Descriptor` split?

**Q-2. The boundary as respecified (N42, N43).** Is the shape rule in scoping order sufficient and implementable
at `_binding_text` as the file stands? Try to break a **named, unshadowed, directly bound** function again with
anything the fifth review did not try, and try to break the *shape rule* with a construction the bare compiler
accepts that the rule as written would classify as named. Is the gate criterion well-defined against the
verdicts `derive_hook_scope` actually emits, and can `emit_hook_scope` implement it without changing the
shipped `ext_ambient_inventory` verdict?

**Q-3. Host-side admission (N47).** Does moving admission to the host keep D6's replay story sound — one exchange
per `Query`, a refusal served from the record, the host re-executing admission from recorded inputs? Is the
child-side mirror's update rule (seeded by the fold, updated by every reply) enough for `prepare` to make an
honest `Immediate` decision, and can it diverge from the host's ledger in a way that matters? Does anything
still require the child to know the per-binding maximum charge?

**Q-4. Identity on orphaning (N46).** Walk every pinned case in D6 and the fourth review's list. Does "orphaning"
fire where it should and only there? Is first registration well-defined for a pre-feature journal and for an
additive profile switch? Do the migration entry and the operator grant close the waiver's unlock, and is
"append a snapshot at zero" enough to stop the second-resume re-refusal?
