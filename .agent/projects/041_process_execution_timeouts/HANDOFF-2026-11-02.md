## Traps this session learned the hard way — pass these to W6's brief

1. **An aggregate gate can fail for a reason that is not the thing you are testing.** I reported
   `0 OK, 0 FAIL` as the guard failing open when `ailang` was simply not on the `PATH` I had set. Measure
   the *mechanism* first, then the aggregate. A delegate that reproduces the mechanism before believing
   an aggregate is doing it right.
2. **A `/tmp` worktree is not a valid baseline.** AILANG auto-relaxes MOD010 there and hides interface
   failures; W5's first base run showed 11 phantom FAILED names and 8 phantom row diffs. Baselines go
   side by side in `/workspaces`.
3. **`make check_core` passes or fails by the caller's `SHLVL`** until #303 lands. After it, it should not
   matter — verify that with both an ambient and an `env -i` run rather than assuming.
4. **`make dst` and `make eval_matrix` run alone**, never beside each other. And `make dst` is red on
   `main` today: `declared_vs_performed`, `adr001_boundary` fixtures, identical at base. W5 worked around
   it by comparing head to base. **This will cost every delegate time until someone fixes it.**
5. **A foreground shell call dies at ~30 s and takes its child with it.** Long targets go in the
   background: `(setsid cmd > log 2>&1 &)` then poll the log. A `nohup ... &` inside the call is not
   enough — the harness killed several of mine that way, and the log ended mid-run with no exit line.
6. **`gh pr edit` fails with the bot token** (needs `read:org`). Use
   `gh api -X PATCH repos/arniwesth/motoko_agent/pulls/<n> -F body=@<file>`. This is in
   `tools/pr/README.md` since #298.
7. **`verify_herdr_orchestrator` creates `./.tmp-herdr-orch/` in whatever checkout it runs from.** A
   delegate running `make` in the shared checkout leaves it behind; it is untracked. Remove it if seen.
8. **`src/core/process_limits.ail:18` names the old checker path** — stale, fix it the next time the
   module changes. #296 moved the checker to `scripts/`.
9. **`new_contract_policy` and `verify_classify` cannot read `VERIFIED (bounded: depth 2)`.** A recursive
   helper verifying that way reports "the module did not compile", which is false. W4 worked around it by
   reusing `decimal_value`. The next such function hits the same wall.
