## §3 — Mechanism checks against HEAD

### 3.1 Stopping contract, settings and reachable arms

**Continuations with calls are correctly described.** `session:4020` routes any nonempty native call list into `tool_calls` even if its finish string differs. `decide` processes pending calls before budget (`step_machine:123–128`), then `call_model_or_fail` fails when a positive budget is exhausted before preparing another call (`:103–118`). With all N tool batches completed and valid resumable history, the stated typed suspension follows (`session:2778–2794,3351–3352`). Source evidence supports r2.1's **299** complete turns, not 300 (`S3/source_check.txt`); the selected seed satisfies the native-call predicate (`S4/scan_v4.txt`: `seed_native_call_predicate True`).

**V4's stop shape is insufficient.** A nonblank assistant with `tool_calls=[]` and `finish_reason="tool_calls"` enters the same tool-state branch; it sets last finish to `tool_calls`, increments step index and has no pending calls (`session:4020–4055`). `decide` consequently falls through to budget/CallModel, not CandidateApproved/Finalize (`step_machine:149–159`). At call N it suspends; before N it continues without a tool result. Either explicitly cut/refuse this shape or define and support it as a separate continuation class. The current “no tool call, non-blank content” stop predicate is wrong (`ADR:465–469`).

For a call-free response whose finish is not `tool_calls`, **hybrid extraction precedes classification** (`session:4058–4066`). With `hybrid_tools=true`, the required predicate is an assistant call whose id does **not** start `hybrid-step-`, anywhere in the accumulated messages (`session:2126–2140`). A hybrid-only seed does not satisfy it. V4 records the “seed with native calls” fact but must enforce it for this class, or pin hybrid=false, or explicitly exclude extracted-call shapes. R2.1 satisfies it; a general message-only T0 start need not (`S4/scan_v4.txt`).

Once classification is reached, the listed verification/solver/persist behavior is correct. Disabled verification returns Approve without `exec`, so `dp7_rejection_errors` returns None (`session:2241–2254,2287–2298`). Empty solver entries collect no decisions and merge to NoDecision (`ext/runtime:683–716,721–727`); persist budget0 prevents the nudge (`recovery:59–61`; `session:3287–3296`). CandidateApproved becomes `dp7_approved` (`session:4135–4155`) and finalizes before the ordinary next-call budget check (`step_machine:149–150`).

**Blank completion is still reachable.** A blank candidate skips stage2, still passes through solver/persist, and stage5 calls the disabled verifier, which again returns None (`session:3267–3305`). It can finalize successfully with empty output and emit `EmptyStopFinalize` (`session:3378–3387`). Settings do not make this unreachable. V4 may exclude it from the admitted class, but must explicitly identify the call-shape cutoff and retain it as a reachable runtime arm; do not rely on a later journal event to identify it (`ADR:470–476`).

`open_waits` starts empty (`session:988–1016`). Native dispatch preserves it (`tool_phase:499–506`); only the Handled lifecycle path shown here adds/removes tool waits (`:438–449`). With empty registry, no restored waits and the runtime-status exclusion, Park/AwaitApproval are unreachable on the valid T0 route (`ext/runtime:426–435,477–493`; `step_machine:123–147`). Feedback, nudge and verifier rejection are similarly excluded by the stated settings; retry/replacement/source user boundaries remain explicit source cuts rather than consequences of the finish predicate (`session:3862–3921`; `ADR:483–490`). Successful history sealing and `project` are still preconditions: invalid history/context can end earlier (`session:3330–3335`; `step_machine:116–118`).

**Two more settings need explicit empty values.** Empty registry does not prevent exit manifest publication: nonempty `MOTOKO_EXIT_MANIFEST` invokes `writeFileResult` and `exec("mv",...)` outside the recorded file port (`session:5066–5097`; `ext/exit_manifest:202–223`). A nonretryable provider fault, including the seam's exhausted error, reads `MOTOKO_CAPTURE_FAILED_PAYLOAD`; a nonempty value invokes an ambient write (`session:3878,1050–1057`). Pin both values empty in the evaluator's synthetic environment, including failure tests. The correct success-path counts remain EXIT_MANIFEST0 on suspension/1 on successful stop, CAPTURE0 on served success; **CAPTURE is read once on a nonretryable provider failure**. Zero recorded mutation witnesses cannot prove absence of those ambient effects (`dst_discovery:473–519`).

**StopBeforeEnd can be coherent as a special post-turn cut.** Retain call k and its assistant append, recompute the selected call count to k, end the selector there and expect Finalize. That is different from the generic before-whole-turn cutoff rule (`ADR:478–480,492`) and needs an explicit exception and matching source transcript selector. The parenthetical “a completed run that resumed in-process” is not established by the traced entry: Finalize returns the result (`session:3354–3409`); source run/resume boundaries are already separate cuts. Describe the observed early eligible stop rather than assert its cause.

### 3.2 Runtime-status cutoff and other tool bypasses

At HEAD the session's built-in callback tests exactly `call.name == "MotokoRuntimeStatus"` and returns a generated message; all other names return None (`session:3677–3681`). `dispatch_tool_entries_with_builtin` appends that message without policy, clock/env read or `tool_exec` (`tool_phase:558–566`). Cutting **before the entire calling turn** is therefore necessary and coherent with A4's queued-tool count, not a matter of restoring that tool's output from source (`ADR:491`; `session:707,757–763`).

For every other eligible tool, empty policy entries yield NoOpinion, which follows the allowed execution arm (`ext/runtime:402–406,426–435`; `tool_phase:608–615`). Empty handle entries yield Delegate with the world threaded/holder cleared (`ext/runtime:477–493`). `ohmy_pi=false` forces Native before name-based backend routing (`tool_phase:452`), and Native reads clock/timeout then calls `ports.tool_exec` (`:484–501`). Thus no other **tool name** bypasses the queued seam on this constrained route. This does not establish absence of unrelated ambient terminal effects; §3.1 identifies two.

### 3.3 Guarded delegation, record cardinality and projection replacement

An evaluator can obtain exported `base = recording_ports(rt)` and call its fields; it need not name private `recording_model_step`, chunk helpers or `tool_outcome_record` (`stub_step:464,621–644`; `ports:886,1024,2087`). Record replacement requires ordinary list/record operations over exported Interaction fields (`dst_interaction:297–302`). The empty-provider/tool branches can use exported `record_interaction`, both outcome codecs and exported outcome/status constructors (`ports:1781–1797,2476–2477,2531`; `dst_interaction:270–276`). No new core export is required.

For a nonempty script, `recording_model_step` consumes one step, plays chunks, selects success/fault result and appends exactly **one** ProviderIdentity record (`stub_step:492–527`). Its empty branch also appends one exhausted record, but the evaluator intercepts it first (`:469–491`). `recording_tool` calls `world_tool` and unconditionally appends exactly one ToolIdentity record for the returned outcome (`ports:2010–2022`). In the scripted branch, correlation mismatch, deadline, failure and completion all return normally after cursor/time advancement (`:1677–1703,1729–1741`); outcome classification is complete (`:2087–2097`). Those paths satisfy the proposed cardinality assertion. This is not a guarantee after an exceptional callback abort; T0 uses no source stream chunks and must keep its callback free of additional log-writing behavior (`ADR:504–538`; `stub_step:121–134,492–527`).

The assertion should preserve the entire prior log prefix and update only the final appended record. It then leaves identity/ordinal, outcome payload/status/class, advance/chunks, world cursors, pending state and emissions unchanged. `world_state_of` decodes outcomes and initial state, not these projection strings; reconstitution uses those queues/classes (`dst_replay:580–601,681–703,761–874`). Discovery still sees identical identity counts/time/env outcomes (`dst_discovery:529–545`). Strict replay intentionally sees the wider request text (`dst_replay:360–365,395`). This is the correct integration.

The empty-tool sketch must spell out a complete `TimedOutcome`, not only `encode_tool_outcome(ToolFailed(...))`: status OutcomeFault, the exported tool-failed catalogue class, no chunks and the chosen advance (normally0), correlated to the returned ToolFailed value (`ports:2087–2097`; `dst_fault_catalogue:61`). Likewise specify the complete exhausted-provider TimedOutcome. Delegation already supplies this consistency on nonempty paths. An unknown tool failure can still become a tool transcript and reach budget suspension; K2/source-chain must reject it separately (`tool_phase:277–296`; `ADR:607–612`).

### 3.4 Exhausted markers and diagnosis

`encode_exhausted_provider_outcome()` produces `{"served":false}`; its decoder returns ProviderScriptExhausted (`ports:2476–2507`). `script_of` skips that record, rebuilding no served step for it (`dst_replay:681–703`). The original interaction remains visible to class counts and strict comparison (`dst_discovery:532–533`; `dst_replay:374–396`). Returning a separately constructed nonretryable Err is feasible; the marker does not serialize that AIError and must never be admitted as a faithful served outcome (`ADR:570–579,688,719`).

**ProgramExhausted is conditional**, not the marker's semantic label. It is emitted when expected interactions are empty and actual has another record (`dst_replay:375–379`). If a marker replaces a still-expected served interaction, comparison can report an identity/projection/outcome mismatch instead (`:360–365,381–386`); if another mismatch occurred earlier, that earlier position remains material. Keep the explicit no-marker A6/K6 check and count mismatch, but promise “fatal divergence; locate the marker and the first mismatch” rather than a universal ProgramExhausted-at-marker diagnosis. A run containing a marker fails A6/K6 by definition even if strict comparison alone had no extra-record condition (`ADR:688,719`).

### 3.5 Program and manifest

The sketch has all ExecutionProgram/InitialWorld fields, and the seed remaining external to the program is accurately disclosed (`dst_program:182–188,243–252`; `ADR:633–658`). `messages_and_policy` is opaque; the corpus entry must supply and verify the actual snapshot-derived `[Message]`, not expect `world_state_of` to parse a seed from that description (`dst_replay:831–874`). Current /4 already carries wake support; /5+ seed/cache work is separate (`dst_program:119–152`).

The binary hash may be encoded in the toolchain string, but the validator does not independently verify that hash or config semantics.

Use `driver_only_manifest` for build-derived fields, not the fixture's literal caller as provenance.
