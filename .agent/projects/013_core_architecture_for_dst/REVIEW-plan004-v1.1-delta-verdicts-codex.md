## §3 — §8 protocol versus the producer

The one-writer rule is technically consistent **for the plan file**: A2 reads `dagr_plan` and writes a separate producer run file, as D:638–644,688–690 and P:668–680 say; the installed v0.3.1 has no `dagr apply` (`dagr --help` lists check/view/stats, not apply), while the unreleased fork has it (D:703–731). `.tmp` → strict check → rename is sound only with the asserted single plan writer (P:675–680). `seed_tasks` skips ids already present (`dagr.ail:256–266`), and the seed carries `state/deps/owner/criteria/note/project`, not `attempts/events/policy` (`dagr.ail:215–246`); terminal tasks receive one `operator`/`reported` attempt (`dagr.ail:223–246`; D:646–650). Thus v2 can carry settled history **in the operator plan file** (P:260–264), but a fresh producer run file does not reproduce that history. Its own observed attempts and the plan's settled attempts can legitimately disagree for the same task; P:679–680 acknowledges non-propagation but gives no reconciliation rule before a gate or delegation. Require a two-file receipt recording both latest task states/attempt ids/verdict evidence, plus explicit authority for gates (operator plan) and producer observations (producer run file); never call a plan settlement producer-observed provenance (`dagr.ail:223–246`; D:640–650).

Fresh session/new file is a reasonable **policy** for structure (P:681–684), but the marker is a session-keyed path, not an immutable declaration: `declare_plan` writes the same marker on another valid declaration (`herdr.ail:585–599`; `dagr.ail:395–397`). D:668–672 says a declaration takes precedence. Correct P:683–684 to say the operator *requires* a fresh session and must verify the marker contents plus first `dagr_task` linkage; the code itself permits redeclaration within a session. An unreadable plan seeds nothing (`dagr.ail:269–284`; D:676–680), so strict-clean operator graph alone does not prove the producer took up v2.
