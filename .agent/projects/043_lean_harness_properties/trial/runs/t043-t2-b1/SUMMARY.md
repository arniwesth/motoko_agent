# T2, the herdr failure vocabulary: summary (arm B, replicate 1)

**Result.** P2.1 and P2.2 are both **false** on the real code. I report **16 findings**, and each
one reproduces on the real, unmodified code (`reports.tsv`; every repro exits 1, the three
controls exit 0):

- **8 violations of P2.1**, each from a separate mechanism. Lean states each as a `bug_`
  theorem, and they account for every P2.1 disagreement in the corpus (1,889 of 9,966 cases).
- **6 violations of P2.2**. Three are K6 (outside herdr's JSON). Three are inside it, or at its
  edge.
- **2 exploratory findings** in the TS host's own contracts, shown end to end through the real
  runner and the real waiter.

What I could prove: when P2.1 holds (`p21_of_agreement`), and a **complete case split** of when
it fails (`p21_disagreement_cases`).

**Step (2) changed the model 2 times.** Both corrections were on the AILANG side, both after
run 1, and both are in how AILANG's `std/json.decode` behaves. The TS side matched on the first
run.

Method: Kiro's, as RESEARCH-lean-harness-properties.md §1 describes it. Toolchain: Lean 4.28.0,
core only (no Mathlib, no Lake); bun 1.4.4; ailang v0.54.14. I executed the real code only for
the differential test (step 2) and the reproductions (step 4). Nothing in the tree was written,
and `git` was not run.

## The model and step (2)

The model keeps the source's structure branch for branch: `tsFailureCode`, `tsMeansAgentGone`,
`failureShape`, `jsonErrorField`, `failureCode` and `meansAgentGone`. Strings are `List Char`.
Both sides' JSON reading is one RFC 8259 parser, `parseJson`, and where the two runtimes differ
the model says so by name:

- The TS side: `jsTrim` (ECMAScript's whitespace set), `jsGet` (the last duplicate key wins).
- The AILANG side: `ailDecode`, `ailGet` (the first duplicate key wins).

| Run | Cases | Model vs TS | Model vs AILANG | Change to the model |
|---|---|---|---|---|
| 1 | 8,328 | 0 | 212 | **Correction 1**: `ailDecode` reads the first complete value and ignores the rest (196 cases). **Correction 2**: `ailDecode` refuses a number whose magnitude rounds to ±∞ as a float64 (16 cases) |
| 2 | 8,514 | 0 | 0 | none. 17 float64-boundary cases added; the model's threshold `2^1024 − 2^970` matched all of them |
| 3 / final | 9,966 | 0 | 0 | none. Cases added on both sides of the edge of the JS whitespace set (U+0085, U+180E, U+200B are not trimmed; U+1680, U+200A, U+2029, U+205F, U+202F are) |

My initial guess of first-wins for AILANG's `get` was right on the first run, so it is not
counted as a correction. One refactor was made for the axiom report, not because of a mismatch:
`numDigits` without `toString`. The Lean output stayed byte-identical.

**Negative control** (`diff/mutants/`, mutants in copies, never in the tree): 3 TS mutants and 2
AILANG mutants give 588 to 1,812 mismatches each, so the test can tell each rule apart.

**What the differential test does not show:** that the model matches the code outside the
corpus. AILANG's `decode` and `get` were learned only from runs, because the AILANG standard
library is outside the two directories I may read. So the model's `ailDecode` is fitted to
9,966 cases, not transcribed. Inputs the corpus does not reach include lone surrogates, invalid
UTF-8, nesting deeper than about 3, and non-integer or NaN exit codes.

## Proved (no `sorry`, no `native_decide`; `axioms.txt`)

All 28 theorems check. 26 use only `propext` and/or `Quot.sound`. Two also use `Classical.choice`
(`ail_not_gone_off_shape` and `fix_p21_of_agreement`), which comes in through core `simp`
lemmas. No theorem uses `sorryAx` or `Lean.ofReduceBool`.

**Where P2.1 holds, and exactly where it fails:**

- `p21_of_agreement` holds for every exit code and stderr. Suppose the exit is positive and not
  2, the stderr passes the extension's sniffs (it contains `{"error"` and not `nested herdr`),
  `JSON.parse(stderr.trim())` and AILANG's `decode` read the same `error.code` `c`, and `c` is not
  a `*_not_found` code other than `agent_not_found`. Then `herdrMeansAgentGone = means_agent_gone`.
  - `p21_of_agreement_witness`: the hypotheses can be satisfied, by herdr's measured envelope.
- `p21_disagreement_cases` holds for every input. If the twins disagree, then one of five cases
  holds:
  1. the exit is negative;
  2. the shape sniff sends herdr's JSON elsewhere;
  3. `JSON.parse` throws;
  4. the decoders read different codes;
  5. the code is another `*_not_found`.

  `p21_cases_inhabited` gives a disagreeing input for each case. The supporting lemmas are
  `ts_not_gone_nonpos`, `ail_not_gone_off_shape`, `ts_not_gone_parse_fails` and
  `neither_gone_on_0_or_2`, with `tsFailureCode_json` and `failureCode_json` for the two codes.
- `p21_measured`: P2.1 holds on every measured herdr case (MEASUREMENTS-2026-08-31 A–E) and on
  `types.ail`'s own test vectors.
- `ail_gone_only_agent_not_found`: the extension is narrow, for every input, as its comment says.
  `ts_gone_iff_suffix`: the host is not.
- **Fix (step 8).** I patched the TS twin with `=== "agent_not_found"` and `r.code === 0`.
  `fix_p21_of_agreement` proves that it agrees with `means_agent_gone` for every exit code once
  the shape and the decoders agree, with no condition on which code was read.
  `fix_closes_suffix_and_negative_exit` checks it on the two witnesses. The fix does not close
  B1-T2-3 to B1-T2-8: those are in the shape sniff and the decoders.

**Not proved:** P2.1 and P2.2 as stated, because both are false. Every counterexample is a `bug_`
theorem proved by `decide` on the model and reproduced on the real code.

## Findings (`reports.tsv`)

**P2.1**: the host and the extension disagree on whether the agent is gone.

| Id | Mechanism | Witness (exit, stderr) | Host / extension |
|---|---|---|---|
| B1-T2-1 | `endsWith("_not_found")` against `== "agent_not_found"` | 1, `{"error":{"code":"pane_not_found",…}}` | gone / not |
| B1-T2-2 | `r.code <= 0` is success to the host | −1, herdr's `agent_not_found` envelope | not / gone |
| B1-T2-3 | `nested herdr` is tested before herdr's JSON | 1, `agent_not_found` with message `nested herdr` | gone / not |
| B1-T2-4 | herdr's JSON is recognised only by the substring `{"error"` | 1, `{"id":…,"error":{"code":"agent_not_found",…}}` | gone / not |
| B1-T2-5 | `trim()` removes Unicode whitespace that AILANG's `decode` refuses | 1, U+00A0 + envelope | gone / not |
| B1-T2-6 | AILANG's `decode` ignores trailing text, `JSON.parse` refuses it | 1, envelope + `\nkilled by SIGTERM` | not / gone |
| B1-T2-7 | duplicate keys: AILANG takes the first, JS the last | 1, `{"error":{"code":"timeout"},"error":{"code":"agent_not_found"}}` | gone / not |
| B1-T2-8 | AILANG's `decode` refuses numbers beyond float64 | 1, envelope with `"n":1e400` | gone / not |

**P2.2**: the codes differ.

| Id | What | Notes |
|---|---|---|
| B1-T2-9 | exit −1 (`killed by SIGTERM`): `""` against `herdr_cli_rejected` | same root cause as B1-T2-2 |
| B1-T2-10 | inside herdr's JSON, for codes that are not `*_not_found`: `timeout` against `nested_herdr` | the host retries on `timeout` (`wake-waiter.ts:359`) |
| B1-T2-11 | empty stderr: `herdr_cli_rejected` against `herdr_failed_silently` | K6 |
| B1-T2-12 | the nested-herdr guard text: `herdr_cli_rejected` against `nested_herdr` | K6 |
| B1-T2-13 | non-envelope JSON (`null`): `herdr_json_undecodable` against `herdr_cli_rejected` | K6. Also contradicts the TS doc comment (`wake-waiter.ts:128`) |
| B1-T2-14 | truncated envelope: `herdr_cli_rejected` against `herdr_json_undecodable` | at K6's edge |

On P2.2's open question, whether the vocabularies are meant to agree outside herdr's JSON: I did
not decide it. B1-T2-11 to B1-T2-13 are marked K6. B1-T2-9, B1-T2-10 and B1-T2-14 show they also
differ **inside** herdr's JSON, or at its edge, where K6 does not reach.

**Exploratory properties:**

- **X-1.** `herdrFailureCode` returns `""` only on success, as its doc comment says
  (`wake-waiter.ts:128`).
  - **B1-T2-15** breaks it through the real runner. `createHerdrRunner` reports a herdr child
    killed by a signal as `code: -1` with no `spawnError` (`:513-514`).
  - `herdrFailureCode` then says `""`, and the wake_reply detail reads
    `failed (exit -1, code ): …`.
  - On that same result, the extension would say the agent is gone (`check.sh B1-T2-2r`).
- **X-2.** The waiter's header rule (`wake-waiter.ts:22-24`): a non-zero exit other than
  `agent_not_found` is `host_error` and never `lost`, as at `means_agent_gone`.
  - **B1-T2-16** breaks it through the real `startWakeWaiter`. A motoko delegate whose row was
    seen and then gets `pane_not_found` is reported `lost`.
  - The detail claims "herdr reports agent_not_found".

**Reachability.** Only one thing is shown reachable: the TS runner producing negative exit codes
with no spawn error (B1-T2-2, -9, -15).

- `pane_not_found` is a real herdr code (`herdr.ail:818`, `types.ail:1965`), but no measurement
  shows `agent get` or `agent wait` returning it. So B1-T2-1 and B1-T2-16 depend on herdr.
- B1-T2-3 to B1-T2-8 need herdr output different from what was measured: other key order,
  pretty-printing, text after the JSON, a BOM, duplicate keys or huge numbers. Each is reproduced
  on the real functions, but none is shown to occur.

**Observation, not reported:** both twins call whitespace-only stderr (`"\n"`) at a failing exit
`herdr_cli_rejected`, not "printed nothing". They agree, so neither property is violated.
