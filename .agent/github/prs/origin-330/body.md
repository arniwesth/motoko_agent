## Summary

Closes #325. On AILANG v0.60.4, now the pin, every Motoko run prints four `LDR006` warnings.
The root package depends on `packages/motoko_scratchpad`, and the package imported four modules
back from `src/core`. AILANG allows that for now and plans to make it an error. This PR removes
all four imports. `ws_loopback` stays in the package, and the line pins on `tool_phase.ail` stay
where they are.

**Why `ws_loopback` stays in the package.** #325's second option was to move `ws_loopback` into
`src/`. Only the core calls it, but under 009 ADR-001 D4 the call at `tool_phase.ail:404` is a core
site attributed to the scratchpad hook (`dst_attribution_table.ail`). The code behind it is
package code, which counts only for profiles that install the package. Moving the module into
`src/core` would make its stream, file, env and network calls core sites. Each would then need an
attribution row or would count for every profile.

**Why no anchor or profile moves.** `tool_phase.ail` needs one new import line. To keep line
numbers fixed, two names in the `phase_vocab` import now share a line (`ToolPlanEntry,
ToolPending,`), as PLAN-002 W2 did. So `tool_phase.ail:403`, `:404` and `:499` stay where they
are, and so do the attribution rows, the six DST scripts that repeat `:404`, and every profile
that records the table's hash. `:404` gains one argument and still calls the same function under
the same guard. `tools/predicate-anchors/anchors.sh` records this next to the two anchors.

Also:

- **`ailang.lock`:** only `sunholo/motoko_ext_scratchpad`'s content hash, interface hash and
  export list change. `generated_at` keeps main's value.
- **`event_subjects.py`:** the code-graph overlay's `ScratchpadResult` note named
  `env_client.ail:118`. It now names `cell_client`. Its subject slugs are unchanged:
  `src/core/env_client` still exists.

Not changed: the package's own `packages/motoko_scratchpad/ailang.lock` was generated by v0.52.5,
so checking a package file prints `VER001`. That was already the case on main.
