Thanks for the report and for the measurements; they are what made this easy to act on. What came of it:

**Suggestion 1, make it visible: done in #239, merged.**

- A session whose model has no context limit now gets one `warning`, once per model. It is a `warning` event on the JSONL wire directly after `context_limit_resolved`, a `[warning] …` line on plain headless stderr, and a line in the TUI history:

  ```
  context limit unknown for openrouter/z-ai/glm-5.3-flash: the model is not in .motoko/model-catalog.json and the profile sets no agent.context_limit. compaction_ai and compaction_structural cannot trigger without a window, so this session's context will grow uncompacted. Set agent.context_limit in the profile's config.json, or add the model under context_limits in .motoko/model-catalog.json.
  ```

- Under `extensions.strict`, a profile that registers a compactor now refuses to start on such a model: one `error` with `error_code: strict_context_limit_unknown`, exit 2. It is opt-in, and no shipped profile is strict.
- A side effect to know about: the plain headless logger used to drop every `warning` event. It now prints them all on stderr, including two lines AILANG writes on each start.

**Suggestion 2, a fallback window: not taken.** Motoko deliberately does not guess a window (`docs/configuration.md`). With the 65,536-token output reservation a 128k guess would leave about 62k of working budget, so a 75% threshold would fire near 46k tokens on a model that may have 1M. `agent.context_limit` already gives a profile its own fallback, as you found.

**Suggestion 3, a fixed token threshold: #240.** One point from it matters for your fleet today. #238 catalogued those models at 1,048,576, and a compactor sees the window minus the output reservation, so `threshold_pct: 75` now fires at about 737k tokens. The run you measured peaked at 260k. With #238 and #239 alone it would still not have compacted, and would have cost the same. Your `agent.context_limit: 262144` workaround does move the trigger, to about 147k. Its price is that the payload seal then ends a run with `compaction_exhausted` at about 187k if the compactors cannot get under that, on a model that has 1M.

**Two things the review of #239 found on the way:**

- #241, merged: with the legacy flat `.motoko/config.json` layout, `agent.context_limit` was loaded and never took effect. If any of your profiles are flat, the override only works from that fix on.
- #242, open: with `WORKDIR` beneath the Motoko repo the runtime loads no profile at all.

Closing this as addressed. #240 carries the cost question.
